ADR-001 Approved

Migration to FCM HTTP v1 Protocol & Admin SDK

Formal decision record superseding deprecated Legacy FCM server keys with modern OAuth 2.0 Service Account authentication.

1. Context & Problem Statement

Google Cloud officially deprecated the Legacy Firebase Cloud Messaging HTTP protocol (https://fcm.googleapis.com/fcm/send) and XMPP server endpoints. Legacy FCM relied on static Authorization: key=AAAA... server keys that presented significant architectural and compliance liabilities:

  • Excessive Scope: Static server keys granted irreversible administrative access across the entire Firebase project.
  • Credential Leak Risk: A compromised server key could not easily be revoked without impacting all dependent microservices.
  • Lack of Modern Platform Features: Legacy payloads could not customize Apple APNs HTTP/2 headers (such as apns-push-type or apns-collapse-id) or Android notification channels directly.

2. Decision Drivers

  • Compliance with Google Cloud deprecation schedules.
  • Enterprise security requirement for short-lived, auto-rotating OAuth 2.0 bearer tokens.
  • Need for granular control over Apple APNs headers, Android notification channels, and Web Push options.
  • High-throughput batch delivery support (up to 500 tokens per multicast operation).

3. Considered Options

Option Pros Cons
Option A: Raw REST Client for FCM HTTP v1 Zero external NuGet dependencies. Requires manually managing Google OAuth2 refresh tokens, JWT signing, and retry backoff.
Option B: Official FirebaseAdmin .NET SDK (Selected) Google-maintained, automatic token caching and renewal, native batching APIs, strongly-typed contracts. Adds dependency on FirebaseAdmin and Google.Apis.Auth.

4. Decision Outcome

Chosen Option: Option B. Adopt the official FirebaseAdmin .NET SDK (version 3.1.0) communicating over the FCM HTTP v1 protocol.

All push dispatches are authenticated using Google Service Account credentials with automated in-memory token refreshes handled by the SDK.

5. Implementation Details

The connector initializes named Firebase applications via FirebaseAppManager:

Services/FirebaseAppManager.csC#
var options = new AppOptions
{
    Credential = GoogleCredential.FromJson(serviceAccountJson)
};
var app = FirebaseApp.Create(options, appName);

Delivery is executed via FirebaseMessaging.GetMessaging(app).SendMulticastAsync(message) or SendAsync(message).

6. Consequences

Positive Consequences
  • Full support for modern Apple iOS 16+ features (Focus bypass, collapse IDs, background data fetches).
  • Eliminates persistent static server keys. OAuth2 tokens rotate automatically every 60 minutes.
  • Multicast responses provide per-token error diagnostics (e.g. distinguishing Unregistered from InvalidArgument).
Trade-offs & Mitigations
  • Service Account JSON files must be secured: Mitigated by injecting credentials via environment variables at container boot (see ADR-004).
