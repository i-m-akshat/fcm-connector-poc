⚡ Real-Time Event-Driven Mobile Architecture

How mobile apps trigger and receive real-time notifications in an enterprise event-driven system: REST Ingress, Message Brokers, FCM Wakeups, and native client Event Emitters.

The Web vs. Mobile Architectural Difference

In web applications, open browser tabs maintain long-lived WebSockets or in-memory EventEmitter instances. In mobile applications, iOS and Android aggressively suspend background apps and kill idle TCP connections to preserve battery life. This manual details the hybrid event pattern used by industry leaders like Uber, Slack, and WhatsApp.

A. Swift (iOS) — NotificationCenter

Swift (iOS)Swift
// 1. In AppDelegate (Foreground Listener):
func userNotificationCenter(_ center: UNUserNotificationCenter,
                            willPresent notification: UNNotification,
                            withCompletionHandler completionHandler: @escaping (UNNotificationPresentationOptions) -> Void) {
    let userInfo = notification.request.content.userInfo
    if let rideId = userInfo["rideId"] as? String {
        // 🔥 Dispatch Event via iOS Native Event Emitter:
        NotificationCenter.default.post(name: NSNotification.Name("OnNewRideReceived"), object: rideId)
    }
    // Show in-app banner or sound:
    completionHandler([.banner, .sound])
}

// 2. In DriverMapViewController (Event Listener / Subscriber):
override func viewDidLoad() {
    super.viewDidLoad()
    NotificationCenter.default.addObserver(self, selector: #selector(handleNewRide(_:)),
                                           name: NSNotification.Name("OnNewRideReceived"), object: nil)
}

B. Kotlin (Android) — SharedFlow / Event Bus

Kotlin (Android)Kotlin
// 1. Singleton Event Hub:
object AppEventBus {
    val rideEvents = MutableSharedFlow<String>(extraBufferCapacity = 1)
}

// 2. In MyFirebaseMessagingService:
override fun onMessageReceived(remoteMessage: RemoteMessage) {
    val rideId = remoteMessage.data["rideId"]
    if (rideId != null) {
        // 🔥 Emit event to active Activities/Fragments:
        CoroutineScope(Dispatchers.Main).launch {
            AppEventBus.rideEvents.emit(rideId)
        }
    }
}

// 3. In MainActivity / Fragment:
lifecycleScope.launch {
    AppEventBus.rideEvents.collect { rideId ->
        showAcceptRideDialog(rideId)
    }
}

C. Flutter (Cross-Platform) — StreamController / EventBus

Dart (Flutter)Dart
// Global Event Stream
final StreamController<String> rideEventStream = StreamController<String>.broadcast();

// Foreground Message Handler
FirebaseMessaging.onMessage.listen((RemoteMessage message) {
  if (message.data.containsKey('rideId')) {
    rideEventStream.add(message.data['rideId']!);
  }
});

// Inside UI Widget:
@override
void initState() {
  super.initState();
  rideEventStream.stream.listen((rideId) {
    showRideModalSheet(context, rideId);
  });
}

D. React Native — DeviceEventEmitter

JavaScript (React Native)JavaScript
import { DeviceEventEmitter } from 'react-native';
import messaging from '@react-native-firebase/messaging';

// 1. Foreground listener emits event:
messaging().onMessage(async remoteMessage => {
  if (remoteMessage.data?.rideId) {
    DeviceEventEmitter.emit('onNewRide', remoteMessage.data.rideId);
  }
});

// 2. Component listens to event:
useEffect(() => {
  const subscription = DeviceEventEmitter.addListener('onNewRide', rideId => {
    openRideModal(rideId);
  });
  return () => subscription.remove();
}, []);

4. Summary: The Golden Rules for Mobile Event Architecture

Architecture Takeaways
  • Never call FCM directly from client apps: Mobile triggers business actions via REST/gRPC. The backend broker triggers the push gateway.
  • FCM is the bridge across OS suspension: It is the only reliable way to reach a user when their phone is locked in their pocket.
  • Use Native Event Emitters in Foreground: When the app is open, catch the push in the foreground listener and emit into NotificationCenter (iOS), SharedFlow (Android), or StreamController (Flutter) for silky-smooth UI updates without reloading screens.
