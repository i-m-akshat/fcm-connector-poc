📱 Mobile Apps & Multi-Project Integration Manual

Complete integration manual for native iOS (Swift), native Android (Kotlin), Flutter, and React Native apps connecting to multi-tenant Firebase projects.

The #1 Question: Do I need a separate backend for iOS?

NO! The .NET Firebase Connector handles both Android and iOS devices using the exact same API endpoint (POST /api/notifications/send). Google FCM automatically translates your message into Apple's native HTTP/2 APNs format behind the scenes.

2. Foolproof Mobile Setup Guide (If your Mobile Dev is Junior or You're doing it Yourself)

Follow these exact click-by-click steps to configure both Android and iOS from scratch without guessing.

🤖 Part A: Android Setup (Android Studio & Gradle)

  1. Register App in Firebase Console:
    • Open Firebase Console > Project settings (⚙️) > General tab > scroll down to Your apps.
    • Click the Android icon.
    • Enter your Android package name (find this in your android/app/build.gradle under defaultConfig { applicationId "com.yourcompany.app" }).
    • Click Register app.
  2. Download & Place google-services.json:
    • Download the google-services.json file.
    • CRITICAL COMMON MISTAKE: Place it inside the android/app/ directory (NOT the root project folder!).
  3. Configure Gradle Files:

    In root android/build.gradle (Project level):

    buildscript {
    dependencies {
        classpath 'com.google.gms:google-services:4.4.1'
    }
}

    In android/app/build.gradle (App level):

    plugins {
    id 'com.android.application'
    id 'com.google.gms.google-services' // Add this at top or bottom
}

dependencies {
    // Import the Firebase BoM
    implementation platform('com.google.firebase:firebase-bom:33.1.0')
    implementation 'com.google.firebase:firebase-messaging'
}
  4. Declare Service & Permission in AndroidManifest.xml:

    Add the Android 13+ permission above <application>:

    <uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>

    Inside <application>...</application>, register the messaging receiver:

    <service
    android:name=".MyFirebaseMessagingService"
    android:exported="false">
    <intent-filter>
        <action android:name="com.google.firebase.MESSAGING_EVENT" />
    </intent-filter>
</service>

🍎 Part B: iOS Setup (Apple Developer Portal & Xcode)

  1. Enable Push in Apple Developer Portal:
    • Go to developer.apple.com/account > Certificates, Identifiers & Profiles > Identifiers.
    • Select your App ID (e.g. com.yourcompany.app) > scroll down to Push Notifications > check the box > click Save.
  2. Create & Download the APNs Key (.p8):
    • In Apple Developer, go to Keys > click `+` to add a key.
    • Name it FCM APNs Key, check Apple Push Notifications service (APNs), and click Continue > Register.
    • Download the AuthKey_XXXXXXXXXX.p8 file. Save it safely (Apple only lets you download it once!).
    • Note down your 10-character Key ID and 10-character Team ID (top-right corner of Apple Developer).
  3. Upload .p8 Key to Firebase Console:
    • Open Firebase Console > Project settings (⚙️) > Cloud Messaging tab.
    • Scroll down to Apple app configuration.
    • Click Upload under APNs Authentication Key > select the .p8 file > enter Key ID and Team ID > click Upload.
  4. Add iOS App to Firebase & Get GoogleService-Info.plist:
    • In Firebase Console > Project settings > General tab > click + Add app > select iOS.
    • Enter your iOS Bundle ID (must match Xcode Bundle Identifier exactly).
    • Download GoogleService-Info.plist.
    • Open your project in Xcode, drag GoogleService-Info.plist into your project navigator, and ensure "Copy items if needed" is checked.
  5. Enable Capabilities in Xcode:
    The #1 Mistake Junior iOS Developers Make

    If you don't enable these two capabilities in Xcode, notifications will NEVER show up and silent pushes will NEVER wake up the app:

    • Open your project in Xcode > select your Target > switch to Signing & Capabilities tab.
    • Click `+ Capability` > double-click Push Notifications.
    • Click `+ Capability` again > double-click Background Modes.
    • Under Background Modes, check:
      • ☑️ Remote notifications (Required for background sync / silent push!)
      • ☑️ Background fetch

⚠️ The Top 5 Mistakes That Cause "Notifications Not Working":

Mistake Symptom How to Fix
1. Testing iOS on a Simulator without Push support getToken() fails or returns invalid token. Always test on a real physical iPhone or ensure Xcode 14+ with APNs Simulator environment is configured.
2. Forgot Xcode Background Modes Alert notifications work, but silent background pushes (data sync) never execute. In Xcode > Signing & Capabilities > Background Modes > check Remote notifications.
3. Android 13 Missing Permission Notifications deliver to device but Android silently drops them. Add POST_NOTIFICATIONS permission and call ActivityCompat.requestPermissions at runtime.
4. Mobile App Never Registers Token with Backend Backend returns "DevicesCount: 0". When mobile app acquires FCM token, it MUST call POST /api/devices/register with its userId and appId.
5. google-services.json in Wrong Folder Android build fails with "File google-services.json is missing". Move it from the project root into android/app/google-services.json.

3. Connecting Existing Apps with Separate Firebase Projects

If your organization has multiple existing mobile apps, each with their own separate Firebase project (e.g. Customer App in Project A, Driver App in Project B):

.env — Multi-Project ConfigurationBash
# App 1: Existing Customer App Project
FIREBASE_APP_CUSTOMERAPP_JSON='{"type":"service_account","project_id":"my-customer-firebase",...}'

# App 2: Existing Driver App Project
FIREBASE_APP_DRIVERAPP_JSON='{"type":"service_account","project_id":"my-driver-firebase",...}'

# App 3: Existing Merchant App Project (Base64 string supported!)
FIREBASE_APP_MERCHANTAPP_JSON=eyJ0eXBlIjoic2VydmljZV9hY2NvdW50IiwicHJvamVjdF9pZCI6...

When client apps register their tokens via POST /api/devices/register, they include their appId (e.g. "appId": "DriverApp"). The connector automatically routes dispatches to that application's dedicated Firebase project!

4. Client Implementation Recipes

A. Swift (Native iOS):

AppDelegate.swiftSwift
import UIKit
import FirebaseCore
import FirebaseMessaging
import UserNotifications

@main
class AppDelegate: UIResponder, UIApplicationDelegate, UNUserNotificationCenterDelegate, MessagingDelegate {

    var currentToken: String?
    let userId = "driver_alex@company.com"
    let appId = "DriverApp"
    let apiBase = "https://your-api.com/api"

    func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
        FirebaseApp.configure()
        Messaging.messaging().delegate = self

        // 1. Request Push Permissions
        UNUserNotificationCenter.current().delegate = self
        UNUserNotificationCenter.current().requestAuthorization(options: [.alert, .badge, .sound]) { granted, _ in
            if granted { DispatchQueue.main.async { application.registerForRemoteNotifications() } }
        }
        return true
    }

    // 2. Receive FCM Token and register with backend
    func messaging(_ messaging: Messaging, didReceiveRegistrationToken fcmToken: String?) {
        guard let token = fcmToken else { return }
        self.currentToken = token
        registerDeviceWithBackend(token: token)
    }

    func registerDeviceWithBackend(token: String) {
        guard let url = URL(string: "\(apiBase)/devices/register") else { return }
        var req = URLRequest(url: url)
        req.httpMethod = "POST"
        req.setValue("application/json", forHTTPHeaderField: "Content-Type")
        let payload: [String: Any] = ["userId": userId, "appId": appId, "deviceToken": token, "deviceType": "iOS"]
        req.httpBody = try? JSONSerialization.data(withJSONObject: payload)
        URLSession.shared.dataTask(with: req) { _, res, _ in
            if let http = res as? HTTPURLResponse, http.statusCode == 200 {
                self.startHeartbeat()
            }
        }.resume()
    }

    // 3. 45-Second Sliding Heartbeat Loop
    func startHeartbeat() {
        Timer.scheduledTimer(withTimeInterval: 45.0, repeats: true) { [weak self] _ in
            guard let self = self, let token = self.currentToken,
                  let url = URL(string: "\(self.apiBase)/presence/heartbeat") else { return }
            var req = URLRequest(url: url)
            req.httpMethod = "POST"
            req.setValue("application/json", forHTTPHeaderField: "Content-Type")
            req.httpBody = try? JSONSerialization.data(withJSONObject: ["userId": self.userId, "deviceId": token])
            URLSession.shared.dataTask(with: req).resume()
        }
    }
}

B. Flutter (Cross-Platform Dart):

main.dartDart
import 'dart:async';
import 'dart:convert';
import 'package:flutter/material.dart';
import 'package:firebase_core/firebase_core.dart';
import 'package:firebase_messaging/firebase_messaging.dart';
import 'package:http/http.dart' as http;

Future<void> initPushClient() async {
  await Firebase.initializeApp();
  NotificationSettings settings = await FirebaseMessaging.instance.requestPermission();

  if (settings.authorizationStatus == AuthorizationStatus.authorized) {
    String? token = await FirebaseMessaging.instance.getToken();
    if (token != null) {
      // 1. Register with backend
      await http.post(
        Uri.parse("https://your-api.com/api/devices/register"),
        headers: {"Content-Type": "application/json"},
        body: jsonEncode({
          "userId": "alex@company.com",
          "appId": "CustomerApp",
          "deviceToken": token,
          "deviceType": "FlutterMobile"
        }),
      );

      // 2. 45-second presence heartbeat
      Timer.periodic(const Duration(seconds: 45), (timer) async {
        await http.post(
          Uri.parse("https://your-api.com/api/presence/heartbeat"),
          headers: {"Content-Type": "application/json"},
          body: jsonEncode({"userId": "alex@company.com", "deviceId": token}),
        );
      });
    }
  }
}
