📬 Notification Types & Payload Specification

Complete reference manual for all 6 FCM notification types, targeting mechanisms (Unicast, Topic, Condition), and platform-specific headers.

Unified Delivery Contract

All push notifications are submitted through a single unified endpoint: POST /api/notifications/send. The router automatically translates fields into native Android Channels, Apple APNs headers, and Web Push options.

1. Visible Alert Notification

Standard push notification that alerts the user with a title, body message, and device sound.

POST /api/notifications/send — Alert RequestJSON
{
  "userId": "alex@company.com",
  "title": "Order Dispatched 🚚",
  "body": "Your order #8291 is on its way to your delivery address.",
  "isSilent": false,
  "priority": "High"
}

2. Silent Push Notification (Background Sync)

Silent pushes do not show any banner, badge, or sound. They wake up the mobile app in the background for up to 30 seconds to fetch data from the server and update local storage.

iOS Requirement

For iOS to deliver silent notifications, the app must have the Background Modes > Remote notifications capability enabled in Xcode, and our backend sets apns-push-type: background and content-available: 1.

POST /api/notifications/send — Silent PushJSON
{
  "userId": "alex@company.com",
  "isSilent": true,
  "data": {
    "action": "SYNC_DATABASE",
    "resource": "orders",
    "updatedAfter": "2026-10-13T00:00:00Z"
  }
}

3. Rich Media Push Notification (With Image)

Displays a high-resolution expandable image banner. Ideal for marketing promotions, map routes, and product previews.

POST /api/notifications/send — Rich MediaJSON
{
  "userId": "alex@company.com",
  "title": "Special 50% Weekend Offer! 🍕",
  "body": "Order your favorite pizza now with coupon WEEKEND50.",
  "imageUrl": "https://images.unsplash.com/photo-1513104890138-7c749659a591?w=800",
  "data": {
    "promoCode": "WEEKEND50",
    "deepLink": "app://offers/weekend"
  }
}

4. Interactive / Actionable Push (Action Buttons)

Allows the user to respond directly from the notification shade (e.g. "Accept" / "Reject") without opening the app.

POST /api/notifications/send — Actionable RequestJSON
{
  "userId": "driver_alex@company.com",
  "title": "New Ride Request: 3.2 km",
  "body": "Pickup at Grand Central Terminal ($18.50 fare)",
  "actionCategory": "RIDE_REQUEST_ACTIONS",
  "priority": "High",
  "data": {
    "rideId": "ride_92812",
    "passenger": "Sarah Connor"
  }
}

5. Collapsible Notification (Live ETA / Live Score)

Prevents flooding the notification tray. When multiple updates arrive for the same tracking item, each new update replaces the previous one on the lock screen.

POST /api/notifications/send — Collapsible ETAJSON
{
  "userId": "alex@company.com",
  "title": "Driver Arriving in 2 Minutes",
  "body": "Toyota Prius (ABC-1234) is turning onto your street.",
  "collapseKey": "ORDER_8291_ETA",
  "priority": "High"
}

6. Time-Sensitive / Critical Notification

Used for critical alerts such as security breaches, fraud warnings, or severe weather alerts. High urgency flags bypass iOS Focus modes and Android Do Not Disturb.

POST /api/notifications/send — Critical AlertJSON
{
  "userId": "alex@company.com",
  "title": "🚨 Urgent Security Alert",
  "body": "Unrecognized login attempt detected from IP 198.51.100.22.",
  "priority": "Critical",
  "data": {
    "sessionId": "sess_81726",
    "action": "LOCK_ACCOUNT"
  }
}

📡 Broadcast & Topic Targeting Modes

In addition to targeting individual users or specific device tokens, the gateway supports high-scale Pub/Sub broadcasting:

A. Topic Broadcast (Publish to Millions)

Broadcasts instantly to millions of devices without needing to maintain large token lists:

POST /api/notifications/send — Topic BroadcastJSON
{
  "topic": "drivers_city_ny",
  "title": "High Demand Surge in Manhattan! ⚡",
  "body": "Surge multiplier 2.5x active in Midtown.",
  "priority": "High"
}

B. Topic Subscription & Management APIs

POST /api/topics/subscribeJSON
{
  "topic": "drivers_city_ny",
  "tokens": [
    "fcm_device_token_1",
    "fcm_device_token_2"
  ]
}

C. Boolean Condition Targeting

Targets devices matching compound boolean expressions of topic memberships:

POST /api/notifications/send — Condition BroadcastJSON
{
  "condition": "'drivers_city_ny' in topics && ('premium_tier' in topics || 'ev_vehicles' in topics)",
  "title": "Exclusive EV Incentive Program 🔋",
  "body": "Earn extra bonus rewards for charging during off-peak hours."
}

D. Presence-Conditional Push (onlyIfActive: true)

When sending notifications that only matter if the user is actively using the app (e.g. live chat typing, live radar ping), set onlyIfActive: true. If the user's heartbeat is older than 90 seconds, the message is skipped, saving server bandwidth and battery life.

POST /api/notifications/send — Active Presence CheckJSON
{
  "userId": "alex@company.com",
  "title": "New in-app chat message",
  "body": "Support agent is typing...",
  "onlyIfActive": true
}
