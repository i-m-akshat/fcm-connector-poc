🏛️ System Architecture

Complete high-level and component topology of the enterprise Firebase Cloud Messaging gateway.

1. End-to-End System Topology

2. Core Components & Responsibilities

1. `PresenceService`

  • Manages device active sessions with Redis key pattern: presence:user:{userId}:device:{deviceId}.
  • Maintains an active set: presence:user:{userId}:devices.
  • Provides an automatic fallback to an in-memory concurrent dictionary if Redis is restarting.

2. `DeviceRegistryService`

  • Tracks registered device tokens for users across all app families (CustomerApp, DriverApp, etc.).
  • Provides automated dead-token pruning: when FCM returns Unregistered or InvalidArgument, the token is automatically deactivated to prevent wasteful re-sends.

3. `FirebaseAppManager`

  • Auto-discovers and registers named FirebaseApp instances dynamically based on environment variables matching FIREBASE_APP__JSON.
  • Decodes both minified raw JSON and Base64-encoded credential strings.
  • Caches FirebaseMessaging clients for ultra-fast dispatch with zero token regeneration latency.

4. `NotificationDeliveryRouter`

  • Enforces the OnlyIfActive presence check.
  • Batches multicast dispatches up to 500 tokens per call (FCM limit).
  • Formats platform-specific payloads for Android (channels, click action, priority) and Apple APNs (sound, badge, interruption level, collapse ID).
