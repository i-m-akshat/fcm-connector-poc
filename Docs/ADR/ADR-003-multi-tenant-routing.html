ADR-003 Approved

Multi-Tenant Routing via Named FirebaseApp Instances

Consolidating multiple independent mobile apps and separate Firebase projects into a single high-throughput routing cluster.

1. Context & Problem Statement

Organizations typically manage a suite of related mobile applications:

  • Customer App: e.g., Firebase Project acme-customer-prod
  • Driver / Courier App: e.g., Firebase Project acme-driver-prod
  • Merchant / Partner App: e.g., Firebase Project acme-merchant-prod

Running isolated push microservices for every mobile app introduces significant infrastructure redundancy, increases cloud hosting bills, and creates multiple Redis and API silos.

2. Decision Drivers

  • Single unified gateway API for all internal backend services.
  • Zero code changes required when provisioning a new mobile app project.
  • Cross-tenant isolation: tokens belonging to one app must never be sent to the Firebase project of another.
  • Support for users registered on multiple apps simultaneously (e.g. an employee who is both a customer and a courier).

3. Decision Outcome

Approved Decision: Implement dynamic multi-tenant routing using Google's named FirebaseApp instances loaded from standardized environment variables:

  • At startup, FirebaseAppManager inspects environment variables for the pattern: FIREBASE_APP_<APP_NAME>_JSON.
  • For each detected variable, the manager deserializes the Google Service Account and invokes FirebaseApp.Create(options, appName).
  • When client apps register their tokens via POST /api/devices/register, they include their appId (e.g. "appId": "DriverApp").
  • During notification dispatch to a user, the NotificationDeliveryRouter groups the target's devices by AppId and sends batches concurrently to each respective FirebaseApp instance.

4. Architecture Blueprint

Services/NotificationDeliveryRouter.csC#
// Group user's registered devices by their assigned application
var devicesByApp = activeDevices.GroupBy(d => d.AppId ?? "FCMPOC");

foreach (var appGroup in devicesByApp)
{
    var appName = appGroup.Key;
    var appInstance = _firebaseAppManager.GetApp(appName);
    var tokens = appGroup.Select(d => d.DeviceToken).ToList();

    var multicastMsg = new MulticastMessage
    {
        Tokens = tokens,
        Notification = ...
    };

    var response = await FirebaseMessaging.GetMessaging(appInstance)
                                          .SendMulticastAsync(multicastMsg);
}

5. Consequences

Positive Impact
  • Infrastructure Consolidation: 1 container cluster serves all 5+ corporate mobile applications.
  • Zero Code Deployment: Adding an existing app requires only adding one line to .env and rebooting the container.
  • Clean Separation: Firebase project quotas, audit logs, and IAM permissions remain strictly isolated per app.
